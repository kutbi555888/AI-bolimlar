Q,K,V
LLMda har bir token yaratilishida Q,K,V vektorlari ham yaratiladi
model har bir keyingi tokenni yaratganda bundan oldingi tokenlarning Key va Value vektorlari kerak boladi.chunki har bir keyingi token ozidan oldingi tokenlarning Key va Value vektorlaridan foydalanib yaratiladi.shu yerda aynan KV Cache(vaqtinchalik xotira,faqat shu savol bergan paytidagina ishlaydi) degan mexanizm kerak boladi

KV Cache bu har bir keyingi token yaratilganda ozidan oldingi tokenlarning Key va Valuelarini vaqtinchalik saqlab turadigan xotiradir.agar KV Cache bolmasa har bir keyingi token yaratilishi uchun ozidan oldingi tokenlarning barcha Key va Valuelarini qaytadan hisoblab chiqish kerak boladi.misol uchun agar 1000 ta token bolsa 1001chi token yaratilishi uchun bundan oldingi 1000ta token Key va Valuelari yana qaytadan boshlab hisoblab yaratilishi kerak boladi.har bir token yaratilganda shunday hamma Key valuelar qaytadan yaratiladi agar KV Cache bolmasa.bu esa juda katta isrof,xarajat,resurs,pul,vaqt ketishiga sabab boladi.

Lekin KV Cache ni bitta muammosi bor:

KV cache juda katta memory,xotira egallaydi.
bu muammo asosan attentionning MHA(Multi head attention)turida uchraydi

KV Cache xotira muammosini hal qilish Attentionnni 3ta turidan birini tanlashga bogliq

Attentionni 3ta turi bor bular:
1.MHA - Multi Head Attention
2.MQA - Multi Query Attention
3.GQA - Grouped Query Attention


Attention inference paytida bitta dona emas.uni koplab boshqa attention head(boshlari) bolib ular ham ishlaydi

MHA - bunda asosan har bir head  bitta Key va Bitta Value ga ega boladi.masalan 20ta attentionni headlari bolsa shu 20tani har birida Bitta Key va bitta Value bor. natija yaxshi,aniq bolishi mumkin lekin xotira juda ham tolib ketish muammosi bor bu Turda

MQA - bunda asosan nechta head bolsa shu umumiy headlarni barchasiga faqat 1ta key va 1ta value beriladi. xotira muammosi yoq, tez, lekin aniqlik kam

GQA - bu balans. MHA kabi aniqroq va MQA kabi tezroq va xotira kop egallamaydi. bunda asosan headlar bir nechta guruhlarga bolinib, shu har bir bolingan guruhga bitta key va bitta value beriladi. masalan 20ta query head bolsa 5tadan 4ta guruhga bolinadi. shu 4ta guruhning har biriga bitta key va bitta value beriladi

 

Context Optimization turlari
Context Optimization modelga uzun contextni imkon qadar kam compute,resurs,xarajat va memory,xotira bilan qayta ishlatishga yordam beradi.chunki har doim ham hamma tokenlar bir biriga qarashi kerak emas bolishi ham mumkin.orniga yonidagi tokenlarga,oxirgi tokenlarga qarash yetarli bolishi mumkin.

1.Full Attention - bu hamma tokenlarga, hamma tokenlar bir bir biriga qarashga,malumot yigishga ruxsat beradi

2.Sparse Attention(siyrak attention) - bunda esa hamma tokenlar bir biriga qaramaydi. faqat bir nechta tokenlar yoki belgilangan tokenlar yoki asosiy tokenlar bir biriga qaraydi
.Sparse Attentionni turlari kop. shulardan biri:
Sliding Window(sirgaluvchi oyna) - Har bir token faqat o‘ziga yaqin bo‘lgan tokenni ko‘radi.

Juda katta hujjat / kitoblarda GQA + Sparse yoki GQA + Sliding Window yaxshi variant
Sababi:
GQA:
KV memoryni kamaytiradi.
Sparse/Sliding:
attention compute complexityni kamaytiradi.


Real-time / streamingda  GQA + Sliding Window yaxshi
Sababi:
yangi data uchun eng so‘nggi context ko‘proq muhim, juda eski ma’lumotni doim ko‘rish shart emas.

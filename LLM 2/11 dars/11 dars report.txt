Serving & Readiness — LLM o‘qitib bo‘lingandan keyin uni foydalanuvchilar ishlata oladigan holatga keltirish va so‘rovlarni qabul qilishga tayyorligini tekshirish jarayonidir.
Bu ikkita alohida, lekin bir-biriga bog‘liq tushunchadir:
Serving — o‘qitilgan LLMni serverda ishga tushirish va foydalanuvchilarning savollariga javob qaytarishini ta’minlash.Servingning asosiy vazifasi  tayyor modelni haqiqiy dastur sifatida ishlatish imkonini yaratishdir.
Serving jarayoni:
API foydalanuvchining savolini qabul qiladi.
Tokenizer matnni token IDlariga aylantiradi.
Model tokenlardan foydalanib keyingi tokenlarni bashorat qiladi.
Inference engine javob tokenlarini hosil qiladi.
Tokenizer javob tokenlarini matnga aylantiradi.
Server tayyor javobni foydalanuvchiga yuboradi.
Serving faqat modelni ishga tushirish emas, balki foydalanuvchi va model o‘rtasidagi butun aloqa jarayonini boshqarishdir.

Readiness esa — LLM haqiqatan ham so‘rovlarni qabul qilish va ularga xizmat ko‘rsatishga tayyormi yoki yo‘qmi, shuni tekshirish.server yoki model hozir foydalanuvchi so‘rovlarini qabul qilishga tayyorligini aniqlaydi.
Readiness nimalarni tekshiradi?
Odatda quyidagi shartlar muhim:
Model Loaded — model vaznlari muvaffaqiyatli yuklanganmi?
Tokenizer Ready — tokenizer ishlashga tayyormi?
GPU/CPU Ready — model ishlashi uchun kerakli resurslar mavjudmi?
Inference Engine Ready — inference mexanizmi ishga tushganmi?
Warmup Completed — agar talab qilinsa, dastlabki sinov hisoblashlari tugaganmi?Serving Warmup — model ishga tushgandan keyin dastlabki hisoblashlarni bajarib, inference tizimini tayyorlash jarayoni.
Critical Dependencies Ready — xizmat uchun majburiy boshqa komponentlar ishlayaptimi?
Request Acceptance — server yangi so‘rovlarni xavfsiz qabul qila oladimi?

LLMda Evaluation va Generation

Evaluation nima?
Evaluation — LLMning bilimini, bashorat qilish qobiliyatini, javob sifatini va umumiy ishlash samaradorligini baholash jarayoni.
Evaluation vaqtida model odatda yangi bilim o‘rganmaydi, ya’ni uning vaznlari yangilanmaydi.
Evaluation nima uchun kerak?
Modelning qanchalik yaxshi o‘qitilganini aniqlash.
Model yangi, ilgari ko‘rmagan ma’lumotlarda qanday ishlashini tekshirish.
Model xatolarini va kamchiliklarini topish.
Turli modellar yoki checkpointlarni solishtirish.
Overfittingni aniqlash — model training ma’lumotlarini yaxshi o‘rganib, yangi ma’lumotlarda yomon ishlashi.
Modelni foydalanuvchilarga taqdim etishga tayyorligini baholash.

Evaluation qanday ishlaydi?
1. Evaluation Dataset
Modelni tekshirish uchun ajratilgan ma’lumotlar
2. Trained LLM
Model test savollariga javob beradi yoki tokenlarni bashorat qiladi
3. Metrics Calculation
Xato va sifat ko‘rsatkichlari hisoblanadi
4. Evaluation Results
Modelning natijalari va kamchiliklari aniqlanadi

Asosiy Evaluation metrikalari
1. Evaluation Loss
Modelning bashorat qilish xatosini ko‘rsatadi.
Odatda pastroq loss yaxshiroq hisoblanadi.
2. Perplexity (PPL)
Til modeli keyingi tokenlarni qanchalik yaxshi bashorat qilishini o‘lchaydi.
3. Accuracy
To‘g‘ri bajarilgan javoblar ulushini ko‘rsatadi. Ayniqsa aniq javobli testlarda ishlatiladi.
4. F1 Score
Precision (model to‘g‘ri deb belgilagan natijalarning qanchasi haqiqatan to‘g‘ri) va Recall (mavjud to‘g‘ri natijalarning qanchasini model topgani) o‘rtasidagi muvozanatni baholaydi.
5. BLEU va ROUGE
Yaratilgan matnni namunaviy javoblar bilan solishtirish uchun ishlatiladigan metrikalar. BLEU ko‘proq tarjimada, ROUGE esa xulosa yaratish kabi vazifalarda ishlatiladi.




Generation nima?
Generation (Text Generation) — o‘qitilgan LLMning berilgan matn asosida yangi tokenlarni ketma-ket yaratish jarayoni.Generationda model odatda bitta tokenni bashorat qiladi, uni mavjud matnga qo‘shadi va keyingi tokenni hisoblaydi.
Generation qanday ishlaydi?
1. Prompt
Foydalanuvchi matni: "Bugun havo..."
2. Tokenization
Matn token IDlariga aylantiriladi
3. Forward Pass
Model keyingi token uchun logits hisoblaydi
Logits — model tokenlarga ehtimollik berishdan oldin hisoblaydigan sonli qiymatlar. Ular odatda Softmax funksiyasi orqali ehtimolliklarga aylantiriladi.
4. Sampling
Keyingi token tanlanadi, masalan "yaxshi"
5. Repeat
Keyingi tokenlar ketma-ket yaratiladi
6. Output
Tayyor matn foydalanuvchiga qaytariladi

Generation qanday usullardan tashkil topgan?
Generation jarayonida keyingi tokenni tanlashning turli algoritmlari mavjud.
Greedy Decoding -  Har safar ehtimolligi eng yuqori tokenni tanlaydi
Beam Search -  Bir nechta mumkin bo‘lgan davomlarni parallel solishtiradi
Temperature Sampling -  Tokenlar ehtimolligi taqsimotining keskinligini o‘zgartiradi
Top-K Sampling  - Eng yuqori ehtimollikka ega K ta token ichidan tanlaydi
Top-P Sampling -  Jami ehtimolligi belgilangan chegaraga yetadigan tokenlar guruhidan tanlaydi
Repetition Penalty -  Takroriy tokenlar tanlanishini kamaytirishga yordam beradi

Generationning boshqa muhim parametrlari ham mavjud:
max_new_tokens — maksimal nechta yangi token yaratilishini belgilaydi.
eos_token_id — matn tugaganligini bildiradigan maxsus token IDsi.
stop_sequence — oldindan belgilangan matn ketma-ketligi paydo bo‘lganda generatsiyani to‘xtatish sharti.
do_sample — tokenlar ehtimollik asosida tasodifiy tanlanishini yoqadi yoki o‘chiradi.

Frontend (Vercel)
 va Backend (Railway) nima?

Biz yaratgan LLMni internetga joylashtirish uchun ikkita platforma

Vercel — Frontendni, ya’ni foydalanuvchi ko‘radigan veb-saytni internetga joylashtiradi.
Railway — Backendni, ya’ni foydalanuvchi so‘rovlarini qayta ishlaydigan server dasturini internetga joylashtiradi.

Vercel
Frontend va veb-ilovalarni joylashtirish platformasi.
Frontend — foydalanuvchi ko‘radigan va foydalanadigan interfeys.
Masalan, bizning LLM loyihamizda:
Savol yoziladigan chat oynasi.
Savolni yuborish tugmasi.
LLM javoblari ko‘rsatiladigan joy.
Veb-sayt dizayni
Kabilar bor
Bular ui/index.html orqali yaratilishi mumkin. Vercel esa shu interfeysni internetga joylashtiradi, shunda foydalanuvchilar brauzer orqali foydalanishadi.


Railway
Server dasturlari va APIlarni joylashtirish platformasi.
Backend — foydalanuvchiga bevosita ko‘rinmaydigan, serverda ishlaydigan dasturiy qism.
LLM loyihasida Backend:
FastAPI serverni ishga tushiradi.
Foydalanuvchining savolini qabul qiladi.
Model va tokenizer bilan ishlaydi.
Inference jarayonini bajaradi.
Tayyor javobni Frontendga yuboradi.
Bizning loyihamizda deployment/app.py Backendning API qismini boshqaradi.
Railway shu Backend dasturini serverda ishga tushirish va internet orqali foydalanish uchun joylashtirishga xizmat qiladi. Katta LLMni ishlatish uchun mos xotira va GPU resurslari alohida talab qilinishi mumkin.
